Towline v0.4.0 is a security and reliability release. It includes everything planned for v0.3.0, which was never published, plus the fixes from a full review of the codebase.

## Upgrading

```bash
towline update
towline refresh --all
```

Then restart your agent sessions. `towline refresh` carries existing projects over: it keeps your other MCP servers and flags, and it adds the bind mounts, external networks and named volumes your deployed stacks already use to each project's allow-lists, so they keep deploying under the stricter compose policy.

**Behavior changes to know about**

- Compose files that join an external network or use an external or explicitly named volume must now be allow-listed in `towline.json` under `compose_policy.allow_networks` / `allow_volumes`. `towline refresh` does this for what's already deployed.
- CLI flags must come before the project name (`towline init --tier prod shop`). Flags placed after it used to be ignored silently; they're now an error.
- `towline destroy` exits non-zero if any Portainer resource was left behind.
- `towline_scale` accepts whole numbers from 0 to 20.

## Approvals

- New built-in approval server: `towline approvals setup | serve | list | show | approve | reject`, with a web UI and optional ntfy notifications. Prod operations can be approved by a human (`human` mode) or confirmed by the agent itself (`agent` mode).
- An approval for one operation can no longer be used to run a different one. Previously, after an approval server restart an agent could get a harmless-looking request approved under its token. Request IDs are now secret and separate from the agent's token.
- Approval tokens are claimed atomically, so concurrent re-calls run an approved operation once.
- The approver always sees the full arguments; oversized ones are refused instead of truncated.
- Pending requests are capped, ntfy pushes no longer include tool arguments, and UI login works behind a reverse proxy (`--public-url`).

## Compose security policy

- Rejected: external or named volumes and external, named or custom-driver networks unless allow-listed; `network_mode` other than `bridge`/`none`; multi-document compose files; privileged `post_start`/`pre_stop` hooks; non-GPU device reservations.
- Names under `.towline` are reserved for Caddy routing, so one stack can't receive another stack's routed traffic.

## CLI

- `towline refresh` upgrades existing projects in place and no longer trusts agent-editable IDs in `towline.json` with the admin key.
- `towline init` in an existing repository merges into your existing `.mcp.json` and agent settings instead of overwriting them, and refuses to run over an existing project or over token files already tracked by git.
- Portainer requests and self-update downloads have timeouts; `--help` exits cleanly.

## MCP tools

- Docker-backed tools (health, logs, exec, `dockerProxy`) now work against an `http://` Portainer, and Docker API errors are reported as errors.
- Parallel tool calls no longer lose each other's changes.
- Logs from TTY containers are no longer mangled, and `since` accepts RFC3339 timestamps, durations like `10m`, or unix seconds.
- `towline_exec` gives up after 30 seconds and returns the output so far.
- Traefik domain edits keep existing labels intact; Caddy routes dial a stack-unique alias.
- `towline_env_set` validates variable names.
