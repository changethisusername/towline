Towline v0.4.1 fixes a v0.4.0 bug that left projects read-only: agents could read their stacks but every deploy failed with HTTP 403.

## Action needed if you used v0.4.0

v0.4.0 gave project teams Portainer's **Read-only user** role instead of **Standard user**. This affects every project you ran `towline refresh` on with v0.4.0, and every project created with `towline init` on v0.4.0. Their agents get errors like:

```
failed to update local stack (HTTP 403): {"message":"Permission denied to access environment","details":"Authorization required for this operation"}
```

To fix them, update and refresh:

```bash
towline update
towline refresh --all
```

Each project should print `Team role set to Standard user`. To fix a project by hand instead: in Portainer, open **Environments**, choose the environment, open **Manage access**, and set the project's team (`team-<project>-<tier>`) to **Standard user**.

## Fixes

- **Team role.** `towline init` and `towline refresh` look up the Standard user role by name from Portainer (`/api/roles`) instead of using a fixed ID, which was the Read-only user role. After setting it they read the role back from Portainer, print its name, and fail (init) or warn (refresh) if it isn't Standard user. They also warn when the team's role can't update stacks. `towline refresh --keep-role` now reports the current role instead of saying nothing.
- **`.gitignore`.** Towline now ignores only the files that hold the project token (`.mcp.json`, `.cursor/mcp.json`, `.gemini/settings.json`, `towline.json`) instead of the whole `.claude/`, `.cursor/` and `.gemini/` directories, which many repositories track. `towline refresh` replaces the directory lines v0.4.0 appended under its "Towline agent configuration" comment; lines you wrote yourself are left alone.
- **Tracked-secrets warning.** `towline refresh` no longer warns that `.claude/settings.json` holds the project token (it doesn't), and `towline init` no longer refuses to run in a repository that tracks `.claude/`.
