Towline v0.5.0 adds the remote gateway: use your Towline projects as a connector in Claude, ChatGPT/Codex and other apps that have no terminal, from anywhere, without opening a port.

## Remote gateway

```bash
export TUNNEL_TOKEN=<cloudflare tunnel token>
towline remote setup --url https://mcp.example.com --all
```

This deploys a `towline-gateway` stack through Portainer: the gateway plus `cloudflared`. The tunnel is outbound-only, so it works behind NAT, CGNAT or double NAT. Then:

1. Open `https://mcp.example.com/ui` and sign in with the owner token that `setup` printed.
2. Create a connection for the projects an app may use, with **Read only** or **Deploy** access.
3. Add `https://mcp.example.com/mcp` as a connector in the app.

Apps connect by signing in during a 10-minute window you open, with a client ID and secret, or with a header token (Claude Code, Cursor). Every change made through the gateway waits for your approval on the gateway page by default, on dev projects too. The gateway holds only each project's own team-scoped key, never the admin key.

Setup, Cloudflare settings and the security model: [docs/remote-gateway.md](https://github.com/changethisusername/towline/blob/main/docs/remote-gateway.md). The gateway image is `ghcr.io/changethisusername/towline-mcp:0.5.0`.

New commands: `towline remote setup | deploy | add | remove | status | owner-token`.

## Fixes for local projects

- **Docker paths.** A Docker API path with an unusual version prefix, such as `/v1.43./containers/<id>/json`, skipped the container ownership check in `dockerProxy`. Docker accepts any run of digits and dots as a version, and now so does the check.
- **Streaming Docker reads are refused.** `dockerProxy` refuses requests that never end: `/events`, `attach`, `stats` without `stream=false`, logs with `follow`, and container `wait`. Use `towline_service_logs` and `towline_service_health` instead.

## Upgrading

```bash
towline update
```

Existing projects need no changes. To serve them remotely, run `towline remote setup`. Projects served remotely need a stack name of at most 24 characters.
